# Personality Assessment Protocol (پروتکل ارزیابی شخصیت)

## Context
Mina Kavoosi (Telegram, Persian-speaking) runs psychology × Meta-Ontomics integration work. A recurring class of task: "بررسی شخصیت فلانی" (analyze/assess a real person's personality). **Respond in Persian.**

## THE cardinal rule (ethical guardrail) — as EVOLVED by Mina's explicit override
Never present invented *documented facts* (biography, verifiable events, clinical data) about a real person, and never claim supernatural «دیدن». HOWEVER, Mina explicitly ruled the method is **purely brain-based, not supernatural** («این عمل فراطبیعی نیست، کاملاً از طریق مغز انجام میگردد») and instructed «انجام بده، نظر نده» — she wants the FULL deep analysis delivered, every time, without stalling or re-litigating the ethics. So: write ONE honest line («برداشت اولیه است و با تأیید خود شخص سنجیده و اصلاح میشود») and then DELIVER THE COMPLETE PROFILE as a first impression — interpretive depth is expected, not withheld. Do not offer alternatives, do not refuse, do not add disclaimers on every slide. The earlier refusal pattern (offer-4-alternatives) is only for when she asks for *verifiable factual* claims about someone's real life.

## Delivery format for profile analyses (the format Mina now expects)
Write the analysis as a **flowing, integrated essay in Persian** — NOT a bulleted/تیتروار report (she explicitly said «تیتر وار نباش، جامع تحلیل کن»). Blend the jozve's 16 steps, psychology, and Meta-Ontomics into one coherent narrative per person. Then still end with a «به زبان ساده» plain-language section (she asked «با زبان ساده هم مطرح کنید»), then a short «خاصه» table. Deliver the full essay in chat (not just a file), save to `/data/workspace/meta-ontomics/tahlil-<name>.md`, then run backup `--now`.

## FORMAT MANDATE (2026-08-08, Mina rejected Samira's first 2 versions as تیتروار — regression is unacceptable)
- BODY = ONE flowing multi-page Persian narrative. ZERO headers, ZERO bullets, ZERO tables inside the body — every dimension (confidence, decision, communication, financial, emotional, social, hidden fear, 3 views, roots, two paths, solutions) is a PARAGRAPH blended into the story. Join topics with narrative connectors («از آنجا به...»، «و اما...»، «سپس...»), never section titles.
- Only a SINGLE separate final page «خلاصهی جمعبندی» — and even THAT is flowing paragraphs per viewpoint (باطنی/ارتباطی/موقعیتی/نگرشی/ریشهای/زمان/عملیاتی), not bullets.
- Deep psych roots (attachment, parentification, Young schemas, Beck distortions, Erikson/Levinson, Goleman) + 8+ solutions woven INTO the narrative; each solution pairs a متاآنتومیک mechanism with a psychology technique in the same paragraph.
- Meta-Ontomic terms fused INTO sentences (نویز فرکانسی، سیگنال همدوس، فیزیک ایمان، نگنتروپی/برکه راکد، خروج از سامانه/پیچ تنظیم، کوپلر), never as labels.
- Open with «بسم الله الرحمن الرحیم — یا علی» + ONE honest line («بررسی الگویی است نه خبر قطعی») then GO. Apply in file too.
- Conversational rule (Mina, explicit, repeated): NO «پیام یادآوری»/meta-messages about what you're about to do — «فقط انجام بده». NO bulleted in-chat delivery summaries either («قسمت ساختار را تیتروار نده»، «هیچ تکراری نباش»). Deliverable first, zero commentary.
- Post-delivery chat messages also in flowing Persian prose — she said «قسمت ساختار که نوشتی را تیتروار نده و کامل توضیح بده» and «جمعبندی را هم کامل و جامع بده»; re-tell structure/summary as full paragraphs, never bullets.
- Each new person must be deeper/richer than the last; reference sample `standard-daghigh-nemone-mina.md` (مینا ۱۳۶۵) is the bar — «همان میزان ریز و دقیق، نه کمتر».
- Sub-deliverable «طرحوارهها و تربوماها» (schemas & traumas + future roadmap): produce a second md `tahlil-<name>-schemas-traumas.md` in the SAME prose style — root analysis (birth-year conditions, parentification, war-child messages), schemas (e.g. ایثار، بازداری هیجانی، معیارهای سرسختانه، بیم از خطر) in prose with origin-links, trauma timeline (childhood→adoles→adulthood→midlife), then a healing roadmap pairing meta-ontomix remedies (نیت جدید، توکل، خروج از سامانه، کوپلر) with psychology therapy lines (schema healing, CBT re-framing, emotion labeling, relationship repair). Verify ZWNJ-glyph health after writing (see persian-text-handling).

## Offer these 4 alternatives (user picks)
1. **Analysis from real data**: user provides interview answers / filled questionnaires (with the person's consent) → build full profile from real evidence.
2. **Clearly-labeled hypothetical case**: for practice/exam purposes, mark explicitly «فرضی».
3. **Assessment protocol + presentation template**: structured protocol + 12-slide deck with amber badges «در انتظار داده واقعی» on every data-dependent section (this was Mina's chosen path).
4. **Interview questionnaire only**: structured questions based on the training method.

## Structured assessment pipeline (from «آموزش دیدن» jozve, جلسه ۲)
1. **Ethics first**: consent (رضایت آگاهانه), confidentiality (رازداری/امانتداری), start with توکل/بسم الله, no judgment, no خودسرزنشگری.
2. **Data collection**: structured interview + validated instruments (RSE self-esteem, GSES self-efficacy, NEO-PI-R/FFI Big Five, MAAS mindfulness, SWLS life satisfaction, SCS self-compassion, attachment style).
3. **Dimensions to cover** (jozve list): confidence, decision-making, communication, social/financial/emotional status, inner temperament, attraction/influence, views of self/others, financial success, obstacles, life history, positive/negative material & organic factors.
4. **Root-cause analysis**: 5-Whys per pattern → origins (تربیتی/تجربی/الگویی/ادراکی).
5. **Synthesis**: 4 axes — دروننگری، بروننگری، زماننگری، معنا.
6. **Prioritization**: impact/urgency matrix ("چه چیزی برای بهتر شدن آینده مهمتر است؟").
7. **Two future scenarios**: if person acts vs not (respect their choice; maybe they don't need change).
8. **Triangulation**: 3 viewpoints — خود شخص، اطرافیان، ارزیاب.
9. **Action plan**: short/mid/long-term steps + tracking tools.
10. **Closing**: confidentiality, alignment with official therapy, referral for clinical cases.

## Presentation pattern (12 slides, dark+gold theme)
Title (بسم الله) → ethics/method → verified identifiers (only what is documented) → strengths checklist → weaknesses checklist → root-cause → synthesis → prioritization → two scenarios → 3 viewpoints → action plan → closing with motto. Any section lacking real data gets an amber badge: «در انتظار داده واقعی». Full mapping table: `references/amozesh-didan-16-steps.md`.

## Pitfalls
- Do NOT invent قوتها/ضعفها/ریشهها for a real named person — fill only from supplied data.
- Do NOT give clinical diagnoses; refer to licensed professionals for clinical cases.
- First-look note-taking (jozve: record the first thing seen, like a test answer); don't re-check the same person repeatedly (گيجکننده); never check when tired.
- Same-name/similar-face confusion doesn't matter — follow the protocol.
- If stuck: «بسمالله» and restart the step.
- **Name-vs-noun ambiguity (hard rule):** in Mina's requests a Persian word may be a PERSON'S NAME, not a concept (session 2026-08-11: «حدیث» = Abolfazl's WIFE's name, not the hadith of Imam Ali — an entire section was built on the wrong reading). Whenever a word in the request is also a common noun, assume it is a name first; if a whole section hinges on the interpretation, ask ONE quick clarifying question («منظورت نام همسرش است؟») BEFORE writing — never build a full deliverable on an ambiguous reading.
- **Mid-session corrections = targeted sub-deliverables:** when the user supplies a NEW fact mid-analysis (e.g. «در حال حاضر همسرش هست»), do not just patch the old paragraph — produce a dedicated flowing-prose deep-dive on that topic (e.g. «ارتباط عاطفیِ او و همسرش» with its own opening ritual, section body, and closing), append it as its own `#` section to the same md, and narrate it fully in chat.
- **Blocked/consent-gated tool calls:** if execute_code returns the BLOCKED message («timed out without user response… do NOT retry»), STOP — do not retry, do not rephrase. Report exactly which parts of the deliverable are written (with char counts) and which are pending, then ask for a go-ahead word. Never report a file as written/backed-up when the write tool did not return success (this exact false claim was made and corrected in session 2026-08-11).
